# Requirements Document

## Introduction

This document specifies the requirements for implementing an Admin Group Management system within the Finance Application. The system enables admins to create and manage groups of regular users, where each admin can view and manage financial data only for users within their assigned group. The feature introduces free-text organization and department entry during registration, along with a group invitation code mechanism for user assignment.

## Glossary

- **Finance System**: The Laravel-based backend application that manages financial transactions, expenses, transfers, and user data
- **Admin User**: A user with role='admin' who can manage a group of regular users and view their financial data
- **Regular User**: A user with role='user' who uploads expenses and can only view their own data
- **Admin Group**: A collection of regular users managed by a specific admin user
- **Group Code**: A unique 4-6 digit numeric code generated by the system for each admin to invite users to their group
- **Organization Name**: A free-text field entered by users during registration (not selected from dropdown)
- **Department Name**: An optional free-text field entered by users during registration (not selected from dropdown)
- **Financial Data**: Includes expenses, transfers, incoming transactions, and fund box records
- **Group Member**: A regular user who belongs to an admin's group

## Requirements

### Requirement 1: Free-Text Organization and Department Entry

**User Story:** As a user (admin or regular), I want to enter my organization and department names as free text during registration, so that I can specify my exact organizational structure without being limited to predefined options.

#### Acceptance Criteria

1. WHEN a user registers, THE Finance System SHALL provide a text input field for organization name
2. WHEN a user registers, THE Finance System SHALL provide an optional text input field for department name
3. THE Finance System SHALL validate that organization name is not empty and contains between 2 and 255 characters
4. THE Finance System SHALL allow department name to be empty or contain between 2 and 255 characters
5. THE Finance System SHALL create or retrieve organization records based on the entered organization name
6. WHERE a department name is provided, THE Finance System SHALL create or retrieve department records linked to the organization

### Requirement 2: Admin Group Code Generation

**User Story:** As an admin user, I want the system to automatically generate a unique group code for me after registration, so that I can share this code with regular users to join my group.

#### Acceptance Criteria

1. WHEN an admin user completes registration, THE Finance System SHALL generate a unique numeric group code between 4 and 6 digits
2. THE Finance System SHALL ensure the generated group code is unique across all admin users
3. THE Finance System SHALL store the group code in the admin user's record
4. THE Finance System SHALL provide an API endpoint that returns the authenticated admin's group code
5. THE Finance System SHALL regenerate a new group code if the admin requests it through an API endpoint

### Requirement 3: User Group Assignment via Group Code

**User Story:** As a regular user, I want to enter a group code during or after registration, so that I can join an admin's group and have my data visible to that admin.

#### Acceptance Criteria

1. WHEN a regular user provides a valid group code, THE Finance System SHALL assign the user to the admin group associated with that code
2. THE Finance System SHALL validate that the provided group code exists and belongs to an active admin user
3. THE Finance System SHALL ensure the regular user and admin belong to the same organization name
4. THE Finance System SHALL allow the regular user and admin to have different department names
5. IF the group code is invalid or belongs to a different organization, THEN THE Finance System SHALL return an error message
6. THE Finance System SHALL allow a regular user to belong to only one admin group at a time

### Requirement 4: Admin Group Member Management

**User Story:** As an admin user, I want to view all members in my group and remove members if needed, so that I can manage who has access to my group.

#### Acceptance Criteria

1. THE Finance System SHALL provide an API endpoint that returns all regular users in the authenticated admin's group
2. THE Finance System SHALL include user details (name, email, department, join date) in the group member list
3. THE Finance System SHALL provide an API endpoint for admins to remove a user from their group
4. WHEN an admin removes a user from the group, THE Finance System SHALL set the user's admin group assignment to null
5. THE Finance System SHALL prevent admins from viewing or removing users who are not in their group

### Requirement 5: Data Visibility Scoping for Regular Users

**User Story:** As a regular user, I want to see only my own financial data, so that my information remains private from other users.

#### Acceptance Criteria

1. WHEN a regular user requests their expenses, THE Finance System SHALL return only expenses created by that user
2. WHEN a regular user requests their transfers, THE Finance System SHALL return only transfers created by that user
3. WHEN a regular user requests their incoming transactions, THE Finance System SHALL return only incoming transactions created by that user
4. WHEN a regular user requests their fund box data, THE Finance System SHALL return only fund box records created by that user
5. THE Finance System SHALL prevent regular users from accessing financial data of other users

### Requirement 6: Data Visibility Scoping for Admin Users

**User Story:** As an admin user, I want to see financial data for all users in my group, so that I can monitor and manage their expenses and transfers.

#### Acceptance Criteria

1. WHEN an admin requests expenses, THE Finance System SHALL return expenses for all users in the admin's group
2. WHEN an admin requests transfers, THE Finance System SHALL return transfers for all users in the admin's group
3. WHEN an admin requests incoming transactions, THE Finance System SHALL return incoming transactions for all users in the admin's group
4. WHEN an admin requests fund box data, THE Finance System SHALL return fund box data for all users in the admin's group
5. THE Finance System SHALL prevent admins from accessing financial data of users outside their group

### Requirement 7: Transfer Restrictions within Admin Groups

**User Story:** As an admin user, I want to create transfers only to users within my group, so that fund movements are restricted to my managed users.

#### Acceptance Criteria

1. WHEN an admin creates a transfer, THE Finance System SHALL validate that the recipient user belongs to the admin's group
2. IF the recipient user is not in the admin's group, THEN THE Finance System SHALL reject the transfer with an error message
3. THE Finance System SHALL allow admins to transfer funds to any user within their group
4. THE Finance System SHALL display only group members as available recipients when an admin initiates a transfer
5. THE Finance System SHALL prevent admins from creating transfers to users outside their organization

### Requirement 8: Organization Matching for Group Assignment

**User Story:** As an admin user, I want users who join my group to be from the same organization, so that group membership is organizationally consistent.

#### Acceptance Criteria

1. WHEN a regular user attempts to join a group using a group code, THE Finance System SHALL compare the user's organization name with the admin's organization name
2. THE Finance System SHALL perform case-insensitive comparison of organization names
3. IF the organization names do not match, THEN THE Finance System SHALL reject the group assignment with an error message
4. THE Finance System SHALL allow users with different department names to join the same group
5. WHERE both users have department names, THE Finance System SHALL not require department names to match

### Requirement 9: Multiple Admins in Same Organization

**User Story:** As an organization, we want to support multiple admins managing different groups within the same organization, so that different teams can operate independently.

#### Acceptance Criteria

1. THE Finance System SHALL allow multiple admin users to have the same organization name
2. THE Finance System SHALL ensure each admin has a unique group code
3. THE Finance System SHALL prevent admins from viewing or managing users in other admins' groups
4. THE Finance System SHALL allow regular users to choose which admin group to join based on the group code provided
5. THE Finance System SHALL maintain data isolation between different admin groups within the same organization

### Requirement 10: Group Code Validation and Security

**User Story:** As the system, I want to ensure group codes are secure and properly validated, so that unauthorized users cannot join groups.

#### Acceptance Criteria

1. THE Finance System SHALL generate group codes using a cryptographically secure random number generator
2. THE Finance System SHALL validate that group codes contain only numeric digits
3. THE Finance System SHALL validate that group codes are between 4 and 6 digits in length
4. THE Finance System SHALL check for group code uniqueness before assigning to an admin
5. THE Finance System SHALL expire or invalidate group codes when an admin account is deactivated or deleted
